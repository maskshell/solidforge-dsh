## Context

Go is already mentioned *aspirationally* in the skill — `SKILL.md` lists `go vet` / `golangci-lint` / `go test` in the generic fast-gate bullet (lines 92–94), `go.mod` in the Graphiti detection list (line 164), and "Go" in the structural-convention sentence (line 392); `role-agent-mapping.md` already has a `.go`/`go.mod` backend-detection row (line 87) and a `Go | testing | go test` test-framework row (line 344); `bug-fix.md` / `refactoring.md` even carry a conflated `Rust/Go/Python` detection row. **But Go is not registered** — it has no `platforms.json` entry, no L4 file, no arch gate, no config template, and no `detect_toolchain` / `fast_gate` / `arm.py` wiring, and the two cross-ecosystem gates (`arch_contract_deps.py`, `arch_contract_tests.py`) have no `go.mod` dispatch. So a Go project armed today gets **zero deterministic gate**: `.go` files fall through `fast_gate.py`'s implicit `else: check_web` (which no-ops), no arch-contract gate runs, and the supply-chain / test gates never dispatch to Go tooling.

The goal is full parity with Java/Rust: a registered language that passes `disconnect_check.py`'s loading chain, is dogfooded by `smoke_gates.py`, AND has functional inner-ring gates (supply-chain via `govulncheck`, tests via `go test`) — not just a `platforms.json` entry that passes the structure checker while the actual gates are inert.

The workspace's own rule (CLAUDE.md rule 1) defines "done" as the skill's deterministic self-gates passing green; rule 3 forbids a silent green. `disconnect_check.py` is the mandatory structure gate and is **fully data-driven** from `platforms.json`; the cross-ecosystem gates, however, hardcode their ecosystem dispatch and MUST be edited by hand (a real touch point the round-1 review caught).

## Design decision — Go is a STRONG gate, not thin (ADR #36)

Java and Rust are documented as **thin** gates ("no first-class layer/dependency-direction enforcer"). Go's toolchain makes Go a **strong** gate — the strongest of the backend languages. (Corrected in round 1: the cycle-rejection axis is the **compiler** via `go build`, not `go vet`.)

| Axis | Tool | Strength | vs Java/Rust |
| --- | --- | --- | --- |
| Format | `gofmt` (built into the Go toolchain) | strong, no config | like google-java-format |
| Static correctness | `go vet` (built-in) — printf-format, struct tags, lock copies, etc. (runs only after `go build` passes — shares the compiler's type-check front-end) | strong | broader static checks than checkstyle style |
| **Import cycles / compile errors** | the **Go compiler** rejects cyclic imports — `go build ./...` fails with "import cycle not allowed" | **strong, compiler-enforced** | far stronger than Java's `jdeps --cyclic` best-effort parse |
| **Layer / dependency-direction** | `internal/` **compiler-enforced** import boundary (structural) **+** `golangci-lint` **depguard** linter (semantic rules between non-`internal` packages; v2 `rules:` config) | **strong — two complementary enforcers** | stronger than Java's Checkstyle ImportControl: Go has BOTH a compiler-enforced structural boundary AND a config-driven semantic layer linter (fedaot-wiki `go-project-layout-conventions`: `internal/` visibility is enforced by the compiler — importing from outside its parent tree is a compile failure; dependency direction is `cmd → internal/pkg`, never reverse) |
| Concurrency baseline | `-race` detector via `go test -race` (ThreadSanitizer-backed; **test-time/runtime, not static** — there is no `go vet -race`) | first-class at test time | Java/Rust gate has none first-class here; but unlike Python's sync-in-async ast scan or Swift's `-strict-concurrency`, Go has no static equivalent — `-race` runs in the test gate, not the static arch gate |
| Supply chain | `govulncheck` (built-in) | strong | parallel to pip-audit / cargo-audit |

Go's honest `coverage` note is **narrower** than Java's: layer-direction **is** enforced two ways — structurally via the compiler-enforced `internal/` boundary, and semantically via the `.golangci.yml` depguard config for rules between non-`internal` packages; cycles **are** compiler-enforced (`go build`). The one axis that is NOT statically enforceable is concurrency: `-race` is runtime/test-time (`go test -race`), so it runs in the test gate, not the static arch gate (round-6 wiki-informed: fedaot-wiki `go-testing-philosophy` names `-race` the concurrency 底线工具, and the canonical `convergence-repair-loop` framework lists concurrency-baseline校验 as a core axis — for Go that axis is test-time only). The degrade matrix: (a) `go` absent → one coverage note ("go toolchain absent — vet/build/gofmt/cycle checks all skipped"), honest no-op pass; (b) only `golangci-lint` absent → narrower note ("depguard layer rules skipped — `internal/` structural boundary still compiler-enforced"), `go vet` + `go build` still run. `gofmt`/`go vet`/cycle-rejection/`internal/`-boundary ship with the `go` toolchain itself.

Recorded as **ADR #36** in `references/design-decisions.md` (next free number; current max is #35 at line 261 — ADRs use the `## N. Title` heading format that omits the literal "ADR" token; #36 verified free).

2. **`infra/scripts/arch_contract_go.py`** — per-language arch gate. Clone the structure of `infra/scripts/arch_contract_java.py` (self-contained `run`/`have`/`emit`/`is_go_project`/`find_marker_dirs` helpers — rule 7: each gate duplicates these, no shared lib). `GATE = "arch-contract-go"`. **Checks, with explicit ordering (round-2 fix: `go vet` shares the compiler's type-check front-end, so it ALSO fails on cycles — build and vet are NOT independent axes; running both unconditionally double-reports cycles):**
   - **First** `go build ./...` (built-in) — surfaces **import cycles** ("import cycle not allowed") and compile errors. Non-zero exit → emit one blocker finding (rule=`compile-or-cycle`, detail = tail of build output) AND **skip `go vet`** with a coverage note "vet skipped — build failed" (avoids reporting the same cycle a second time as a vet load-phase failure, which would inflate the thrashing breaker's distinct-fingerprint count). If build passes, proceed.
   - **Then** `go vet ./...` (built-in, only if build passed) — parse text output `<file>:<line>:<col>: <message>` → blocker findings (rule=`go-vet`). (Vet's static checks — printf-format, struct tags, lock copies — only run once the package compiles.)
   - `golangci-lint run --out-format=json` (optional) — parse JSON `Issues[]` (`FromLinter`, `Pos.Filename`/`Pos.Line`, `Text`, `Severity`). **Severity mapping by linter name (round-2 fix W3: golangci-lint's `Severity` field is EMPTY by default — only populated when a `severity` config section exists — so `FromLinter` is the primary signal; do NOT mirror Java's `arch_contract_java.py:116-117` string-equality on a severity field):** `depguard` (layer violations) + `govet` → **blocker**; `gofmt`/`gofumpt`/`whitespace`/other style lints → **warning**; default → **warning**. **Precedence (round-3 NIT): `FromLinter` is primary; a configured `Severity` may only PROMOTE an unmapped linter to blocker — it must never demote `depguard`/`govet` to warning** (equivalently, omit the `severity` section from the `.golangci.yml` template so the field stays default-empty and cannot contradict the map). Do NOT map all findings to blocker (rule 4 — a `gofmt` reformat suggestion is not a convergence Blocker).
   - **Degrade matrix:** `go` absent → single coverage note, pass (honest no-op); `go` present but `golangci-lint` absent → run build+vet, coverage note "depguard layer rules skipped"; invocation failure of any tool → coverage note, continue.

3. **`infra/templates/.golangci.yml`** — config. Mirror `infra/templates/checkstyle.xml` (commented layer-rule block + doc header). ## Cross-ecosystem gates (the part that makes Go FUNCTIONAL — round-1 blocker B1)

These two gates are NOT data-driven; they hardcode their ecosystem dispatch loops and **must be edited by hand** (verified: `arch_contract_deps.py:430-441` and `arch_contract_tests.py:483-499` loop over pyproject/package.json/Cargo.toml/Package.swift/pom.xml/build.gradle — no `go.mod`). Without these edits Go is "first-class" in `platforms.json` but has no functional supply-chain or test gate as Blocker inputs (a silent green, rule 3).

- **`infra/scripts/arch_contract_deps.py`**: add `is_go(root)` (marker `go.mod`), a pure `parse_govulncheck(findings, osv_index)` parser, a `check_govulncheck(root, findings, coverage)` wrapper, and a `for d in find_marker_dirs(root, ["go.mod"]): check_govulncheck(...)` loop in `main()` (root + nested Go modules both scan, matching the other ecosystems). **Round-2 + round-3 fix (BLOCKER): `govulncheck -format json ./...` emits NDJSON — a stream of newline-delimited typed `Message` objects, NOT a single JSON document.** Two compounding facts the parser must handle: (1) the existing `_json_or_none` (`json.loads`, single-doc) would throw `JSONDecodeError` on the stream → the `check_govulncheck` **wrapper** must split stdout on newlines and `json.loads` each line; (2) **round-3:** a `finding` message carries only `{OSV: <id>, FixedVersion, Trace}` — `OSV` is an ID *reference*, and the vulnerability's `summary`/`details` live ONLY on the separate `osv`-typed message emitted earlier in the stream (Go's OSV subset has no CVSS field at all). So the wrapper must collect BOTH `osv` and `finding` messages, build `dict[osv_id -> osv_entry]`, and pass `(findings, osv_index)` to the pure `parse_govulncheck` parser, which joins each finding to its OSV entry to fill `detail` (summary + fixed-version + trace). **Severity: govulncheck reports only *reachable* vulns (all real by definition) and neither message carries CVSS — map ALL govulncheck findings to `blocker`** (parity with `parse_cargo_audit`, which treats every RUSTSEC as blocker); drop any "severity by CVSS" notion. The wrapper degrades to a coverage note when `govulncheck` is absent (rule 3). **The canned unit-test fixture in `arch_deps_parsers.py` MUST use real multi-line NDJSON containing BOTH an `osv` line and a `finding` line that references it, and assert the parser joins them (summary appears in `detail`)** — a finding-only or single-doc fixture would pass offline while real output yields detail-less findings (the silent-green B1 was meant to cure).
- **`infra/scripts/arch_contract_tests.py`**: add a pure `parse_go_test(text)` parser (`go test -json` emits NDJSON lines with `Action`/`Package`/`Test`/`Output`; `Action=="fail"` → blocker finding, rule=`test-failure`), a `check_go(root, findings, coverage)` wrapper, and a `for d in find_marker_dirs(root, ["go.mod"]): check_go(...)` loop in `main()` (with `attempted = True`). **Round-6 wiki-informed: `check_go` runs `go test -race -json ./...` — `-race` (ThreadSanitizer-backed) is Go's canonical data-race detector and IS the concurrency baseline the design table claims; fedaot-wiki `go-testing-philosophy` names it the 底线工具 and the canonical `convergence-repair-loop` framework lists concurrency-baseline校验 as a core axis. `-race` is runtime/test-time (there is no `go vet -race`), so it belongs in THIS test gate, not the static arch gate. Race-induced failures surface as `Action=="fail"` → blocker (data races are undefined behavior per the Go memory model). The `-race` overhead is acceptable because the test gate runs at the inner convergence point, not per-edit.** Degrades to a coverage note when `go` is absent.
- **Parser unit tests (round-1 implication):** the pure parsers above must have canned-JSON/text unit tests added to `infra/test/arch_deps_parsers.py` (`parse_govulncheck`) and `infra/test/arch_tests_parsers.py` (`parse_go_test`) — these are offline parser tests listed in install.md self-checks. Without them the parsers are unverified.
